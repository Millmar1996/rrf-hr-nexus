# Business rules

- **Employee identity:** employee number is unique. Employee records are archived, never hard-deleted by normal HR workflows.
- **Lifecycle:** each recorded event stores its employee, enum type, effective date, before/after JSON, notes, actor, and database timestamp. The lifecycle RPC updates current employee fields when a new value is supplied.
- **Regularization:** only active/probationary employees with a regularization date are due. The event moves status to Active and employment type to Regular where those reference values exist.
- **Client assignments:** the active client is derived from the assignment with no end date. Reassignment ends the prior row and inserts a new row; history is retained.
- **Separation:** stores a Separation event and effective date, marks status Separated and archived, closes active client assignment, releases active resource assignments, and retains employee documents and history.
- **Rehire:** a Rehire event reactivates a retained employee and can establish a current client assignment.
- **201 compliance:** required active document requirements are joined to uploaded metadata. No file means Missing; expiry before today means Expired; expiry within 30 days means Expiring soon; otherwise Complete. Dashboard and reports use the same calculation. Binary files remain in private Storage.
- **Empty compliance population:** when there are no employees to assess, dashboard, 201 Files, Reports, and Monthly HR Report show 0% with zero issue counts. If employees exist but no active required document types are configured, their compliance is treated as complete because there are no requirements to miss.
- **Resources:** assignment history is append-only. Active assignment means Assigned; release returns the resource to Available. Maintenance and Inactive remain explicit non-assigned states.
- **Audit:** table triggers write actor, action, entity, old/new row data, and timestamp. Audit records are not editable through application policies.
- **Monthly workforce changes:** counts and affected employees are calculated from lifecycle records by effective date and event type for month/year or custom range; no summary rows are saved.
- **Upcoming dates:** birthdays and anniversaries are derived from employee birthday and hire date. Regularization alerts are derived from employment status and regularization date.
- **Monthly HR report:** `/reports/monthly` and the Excel/PDF exports consume the same server-generated dataset from employees, lifecycle events, client assignments, document requirements/documents, resources, and resource assignments. No monthly report rows or manually entered totals are stored.
- **Monthly boundaries:** date-only fields are compared inclusively from the first through the last calendar day of the selected month. Generated timestamps and date display use `Asia/Manila`. Timestamped document/resource records are converted to their Manila calendar date before period checks.
- **Headcount:** the period-end snapshot includes employees hired on or before the last day. Total includes separated records; active means hired and not separated (employees on leave are included in active). Probationary and regular are employment-type counts. Separation, rehire, status-change, and regularization lifecycle entries are applied by effective date; where later status events exist, their recorded previous values are used to reconstruct earlier periods. New hires use a HIRE event when present, with `date_hired` as the fallback. Month-to-month headcount and employment-type comparisons are reconstructed from those same records, not saved snapshots.
- **Movement classification:** hire, regularization, promotion/position change, transfer, department transfer, location transfer, client reassignment, and separation sections use effective-dated lifecycle events. Client assignment rows also supply reassignment history when a previous assignment ends on the new assignment start date. Separation notes are omitted from report exports.
- **Regularization monitoring:** completed items are REGULARIZATION events effective in the month. Due-next-month and overdue lists use the employee's expected regularization date and probationary state at the selected period end; completed records are not treated as pending.
- **201 compliance:** active required document types define the requirement denominator. A missing required record is Missing; an expiry before the reporting month end is Expired; an expiry within 30 days after period end is Expiring. Completion counts only documents classified Complete, matching the 201 files screen's completion rule. The current schema does not version deleted/replaced documents, so past compliance cannot be reconstructed perfectly; the report states this limitation.
- **Resource statistics:** inventory status and workstation totals use current resource records. Monthly assignment/release activity comes from dated resource-assignment rows. Current inventory is not a historical snapshot; previous-month workstation comparison is omitted rather than presented as historical fact.
- **Birthdays and anniversaries:** birthdays are listed by month/day only, without birth year or age. Anniversaries use the hire month and calculate completed years of service at the selected reporting year.
- **Master data:** department, position, employment type/status, client, location, document requirement, and resource type values are deactivated rather than deleted when no longer in use.
